# 00. 프로젝트 개요

## 원본 프로젝트 (2022)

**「딥러닝에 기반한 퍼스널 컬러 분석」** — 동의대학교 컴퓨터공학과 5조, 2022년 6월 제출.

### 원본 파이프라인 복원

남아 있는 결과보고서와 발표자료 15장에서 역으로 복원한 구현 흐름입니다.

```
Selenium 크롤링          구글·네이버 이미지 검색
      ↓                   ("쿨톤 연예인" / "웜톤 연예인")
Haar Cascade            cv2.detectMultiScale(gray, 1.2, 3)
      ↓                   얼굴 영역 crop
색공간 분리              BGR → YCrCb  /  BGR → Grayscale
      ↓
이중 마스킹              cv2.inRange(YCrCb, lower, upper)   ← 피부색 범위
      ↓                  cv2.threshold(gray, THRESH_OTSU)   ← 자동 이진화
                         두 마스크를 bitwise_and
      ↓
리사이즈 · 저장          cv2.resize(skin, (128, 128)) → .jpg
      ↓
데이터셋                 X: 이미지 배열, Y: 라벨 (0=cool, 1=warm)
      ↓                  train_test_split → .npy 저장
CNN 학습                Conv2D 64 → 128 → 256 → 256
                        Dense 128 → 32 → 1 (sigmoid)
      ↓
결과                    accuracy ≈ 0.79, val_accuracy ≈ 0.82 (10 epoch)
                        matplotlib으로 이미지와 라벨 출력
```

### 원본이 잘한 것

Otsu 이진화와 YCrCb 범위 마스크를 **교집합**으로 쓴 선택은 지금 봐도 타당합니다. YCrCb `inRange`만 쓰면 배경의 나무·벽돌 같은 피부 유사색이 통과하고, Otsu만 쓰면 밝기만 보므로 밝은 옷이 통과합니다. 둘을 `bitwise_and`로 묶으면 "피부색 범위 안에 있으면서 동시에 얼굴 안에서 밝은 쪽"만 남습니다. 이 아이디어는 재구축에서도 그대로 계승합니다.

### 원본의 한계 — 보고서가 직접 지목한 것

보고서 「프로젝트 결과 논의」에 이렇게 적혀 있습니다.

> 측정에 정확성 문제가 있다. 환경·조도·카메라·각도 등 영향을 끼칠 수 있는 변수가 상당히 많아 정밀한 이미지 데이터셋을 만들 수 없다. (…) 데이터 전처리와 환경에 따른 채도 변화를 해결하거나 얼굴의 윤곽이 학습될 수도 있기 때문에 확실하게 피부색만 추출할 수 있도록 보완할 것이다.

이 진술은 세 개의 서로 다른 문제를 한 문장에 압축하고 있습니다. 재구축에서는 이를 분리해서 각각 대응합니다.

| # | 문제 | 원인 | 재구축의 대응 |
|---|---|---|---|
| **P1** | 조도에 따라 같은 사람이 다르게 판정됨 | 화이트밸런스 미보정 | Gray-World / Retinex 정규화를 전처리 첫 단계로 |
| **P2** | 피부색이 아니라 얼굴 윤곽이 학습됨 | 마스크가 128×128 이미지 형태를 유지 → CNN이 실루엣을 특징으로 잡음 | 이미지가 아니라 **색채 통계 벡터**를 분류기 입력으로 사용 |
| **P3** | 라벨 신뢰도가 낮음 | "웜톤 연예인" 검색 결과는 누군가의 주관 + 보정된 사진 | 규칙 엔진을 기준선으로 두고 학습 모델은 대조군으로 검증 |

**P2가 특히 중요합니다.** 원본은 마스킹한 얼굴을 그대로 CNN에 넣었습니다. 128×128 이미지에는 피부색뿐 아니라 얼굴형·헤어라인·마스크 구멍(눈·입) 모양이 전부 들어 있습니다. CNN은 라벨과 상관관계가 있는 아무 신호나 잡으므로, 특정 얼굴형이 특정 라벨에 몰려 있으면 그걸 학습합니다. 데이터가 적을수록 이 지름길을 택할 확률이 높아집니다.

재구축은 분류기 입력에서 공간 정보를 아예 제거합니다. 피부 픽셀 집합 → 색채 통계 벡터(L\*, a\*, b\*, C\*, h°, ITA°) → 분류. 얼굴형은 물리적으로 입력에 들어갈 수 없습니다.

## 재구축 목표

### 기능 목표

1. 사진 업로드 또는 웹캠 촬영으로 **4계절 퍼스널 컬러** 판정
2. 전처리 각 단계를 UI에서 **시각화** — 발표자료 6번 슬라이드의 흐름도를 인터랙티브하게
3. 판정 근거를 **수치와 그래프로 설명** (블랙박스 탈출)
4. 계절별 **추천 팔레트 및 피해야 할 색** 제시
5. 분석 이력 저장 및 재조회

### 엔지니어링 목표

이 프로젝트는 포트폴리오이기도 합니다. 다음을 의도적으로 드러냅니다.

- **폴리글랏 MSA** — Spring Boot와 FastAPI 간 서비스 경계 설계 및 통신
- **테스트 가능한 도메인 설계** — I/O에 의존하지 않는 순수 도메인 계층
- **실험 기반 의사결정** — 규칙 엔진 vs CNN을 실제로 측정해서 비교
- **결정의 기록** — ADR로 "왜 이렇게 했는지"를 남김

### 명시적 비목표

범위를 지키기 위해 하지 않을 것들입니다.

- 8세부 타입(봄 라이트/브라이트 등) 분류 — 4계절도 사진 한 장으로는 이미 어렵습니다
- 화장품 커머스 연동
- 모바일 네이티브 앱
- 실시간 영상 스트림 분석

## 왜 이 문제가 어려운가

퍼스널 컬러 진단은 본질적으로 **역문제(inverse problem)** 입니다.

카메라가 기록하는 픽셀값은 다음의 곱입니다.

```
관측 픽셀 = 피부의 분광 반사율 × 조명의 분광 분포 × 카메라 응답 곡선 × 보정 파이프라인
```

우리가 알고 싶은 건 첫 번째 항 하나뿐인데, 나머지 셋은 사진마다 다르고 메타데이터에도 남지 않습니다. 오프라인 진단소가 표준 조명 아래에서 진단천을 대는 이유가 정확히 이것입니다 — 나머지 항을 물리적으로 고정하는 겁니다.

사진 한 장으로 이걸 완벽히 풀 수는 없습니다. 그래서 이 프로젝트의 태도는 이렇습니다.

> **정확도를 과장하지 않고, 불확실성을 함께 보고한다.**

신뢰도 계수, 확률 분포, 입력 품질 경고가 결과와 항상 같이 나가는 이유입니다. "당신은 가을 웜입니다"보다 "가을 웜 46% / 겨울 쿨 44% — 두 계절 경계에 있어 다른 조명에서 재측정을 권합니다"가 정직한 답입니다.
