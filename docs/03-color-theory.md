# 03. 색채 이론과 분류 알고리즘

이 문서는 `ml-service/app/domain/` 아래 세 모듈의 이론적 근거를 설명합니다.

---

## 1. 왜 RGB로는 안 되는가

RGB는 **장치 좌표계**입니다. 모니터의 형광체 세 개를 얼마나 밝힐지에 대한 값이지, 사람이 색을 어떻게 느끼는지와는 무관합니다. 구체적으로 두 가지 문제가 있습니다.

**첫째, 거리가 지각과 비례하지 않습니다.** RGB 공간에서 똑같이 30만큼 떨어진 두 색 쌍이, 눈으로는 하나는 거의 같아 보이고 다른 하나는 확연히 다를 수 있습니다.

**둘째, 축이 독립적이지 않습니다.** "노란기를 조금 빼고 싶다"를 RGB로 표현하려면 R·G·B를 동시에 조정해야 합니다. 언더톤 하나만 재고 싶은 우리 문제에는 최악의 좌표계입니다.

### CIELab

CIE가 1976년에 표준화한 **지각 균등 색공간**입니다.

| 축 | 범위 | 의미 |
|---|---|---|
| `L*` | 0 ~ 100 | 명도 (0=흑, 100=백) |
| `a*` | 약 -128 ~ +127 | 녹(-) ↔ 적(+) |
| `b*` | 약 -128 ~ +127 | 청(-) ↔ **황(+)** |

**`b*` 축 하나가 곧 언더톤입니다.** 노란기가 강하면 `b*`가 커지고, 푸른기가 돌면 작아집니다. 이 직접성이 CIELab을 1차 좌표계로 선택한 이유입니다.

### 변환 경로

```
sRGB (0~255)
   ↓  ÷255
sRGB (0~1, 감마 인코딩됨)
   ↓  srgb_to_linear()       ← 이 단계를 빠뜨리면 안 됨
선형 RGB
   ↓  × SRGB_TO_XYZ 행렬
CIEXYZ (D65 백색점)
   ↓  세제곱근 곡선
CIELab
```

> ⚠️ **감마 제거는 선택사항이 아닙니다.**
> sRGB에 저장된 값은 이미 `≈ x^(1/2.2)` 로 인코딩된 상태입니다. 이걸 풀지 않고 XYZ 행렬을 곱하면 밝기가 체계적으로 왜곡되고, 결과적으로 `L*`이 틀어져 봄과 가을을 가르는 명도 판정이 통째로 무너집니다.
>
> 검증: sRGB `(128,128,128)`의 올바른 `L*`은 **50이 아니라 53.6**입니다. 이 값이 50 근처로 나온다면 선형화가 우회된 것입니다. (`test_gamma_removal_is_not_identity`가 이걸 지킵니다.)

### LCh — 극좌표 변환

`a*`/`b*` 평면을 극좌표로 바꾸면 우리가 원하던 두 값이 그대로 나옵니다.

```
C* = √(a*² + b*²)          채도 — 원점에서의 거리 = 색의 선명함
h° = atan2(b*, a*)         색상각 — 각도 = 색 그 자체
```

퍼스널 컬러의 두 축이 정확히 여기 대응합니다. `h°`가 언더톤(웜/쿨)을, `C*`가 클리어/뮤트를 결정합니다.

### YCrCb는 왜 남겨뒀는가

원본 프로젝트가 피부 마스킹에 쓰던 색공간입니다. 휘도(Y)와 색차(Cr, Cb)를 분리하므로 조명 변화에 비교적 둔감해서, **"피부인가 아닌가"** 라는 이진 판정에는 여전히 유효합니다.

다만 균등 색공간이 아니므로 **"언더톤이 얼마나 따뜻한가"** 라는 정도 측정에는 쓰지 않습니다. 역할을 이렇게 나눕니다.

| 목적 | 색공간 |
|---|---|
| 피부 픽셀 선별 (마스킹) | YCrCb |
| 언더톤·명도·채도 측정 | CIELab |

## 2. ITA° — 피부 명도의 표준 지표

```
ITA° = arctan( (L* - 50) / b* ) × 180/π
```

Chardon 등이 1991년에 제안했고 이후 피부과·화장품 업계가 사실상 표준으로 채택한 지표입니다.

**단순히 `L*`만 보지 않는 이유:** 같은 밝기여도 황색도가 다르면 사람 눈에는 다른 톤으로 읽힙니다. `L*=50`을 원점으로 두고 명도와 황색도가 이루는 **각도**를 재면 이 현상이 자연스럽게 흡수됩니다.

### 표준 6단계 구간

| 구간 | ITA° |
|---|---|
| Very light | > 55° |
| Light | 41° ~ 55° |
| Intermediate | 28° ~ 41° |
| Tan | 10° ~ 28° |
| Brown | −30° ~ 10° |
| Dark | < −30° |

> **주의** — 이 구간은 원래 자외선 광손상 위험도 분류용으로 만들어졌습니다. 퍼스널 컬러의 밝기 감각과 정확히 일치하지 않으므로, 분류기의 중립점은 구간 경계(41°)가 아니라 동아시아인 ITA° 분포 중앙 대역(45~50°)에 맞춰 **48°** 로 잡았습니다.

### 수치 안정성

`b*`가 0에 수렴하면 각도가 발산합니다. 실제 피부는 멜라닌과 카로틴 때문에 `b*`가 항상 양수(대개 +10 이상)라 현실에서는 발생하지 않지만, 비정상 입력에 대비해 하한을 둡니다.

## 3. 왜 평균이 아니라 중앙값인가

마스킹을 아무리 정교하게 해도 피부 영역에는 잔여 오염이 남습니다.

- 눈썹·속눈썹 경계의 어두운 픽셀
- 하이라이트로 날아간 흰 픽셀
- 마스크 가장자리의 배경 혼입

**평균은 이런 극단값 몇 개에 통째로 끌려갑니다.** 5,000개 피부 픽셀에 순백 픽셀 500개가 섞이면 평균 `L*`이 눈에 띄게 올라가고, ITA°가 한 구간 위로 밀려 봄이 될 사람이 여름이 됩니다.

중앙값과 사분위 범위는 전체의 25%가 오염돼도 흔들리지 않습니다. 여기에 명도 기준 상·하위 10% 절사를 추가해 그림자와 하이라이트를 한 번 더 걷어냅니다.

절사 기준을 **색상이 아니라 명도(`L*`)로** 잡은 것은 의도적입니다. 오염 픽셀은 색상보다 밝기에서 먼저 튀기 때문입니다.

> 회귀 테스트: `test_median_resists_outliers` — 전체의 15%를 순백으로 오염시켜도 `L*` 변화 2 미만, `h°` 변화 3° 미만.

### 조명 균일도라는 부산물

`L*`의 사분위 범위(IQR)는 그 자체로 유용한 신호입니다. 얼굴에 균일한 조명이 떨어졌다면 IQR이 작고, 한쪽에 그림자가 지거나 역광이면 커집니다.

이 값을 **입력 품질 계수**로 환산해 신뢰도에 반영합니다. 사용자에게는 *"조명이 고르지 않습니다"* 라는 경고로 표시됩니다.

## 4. 4계절 분류 — 프로토타입 거리 방식

### 2×2 격자

```
              Warm (h° 높음)        Cool (h° 낮음)
   Light   │   🌸 봄 웜           │   ☀️ 여름 쿨
   ────────┼─────────────────────┼───────────────────
   Deep    │   🍂 가을 웜         │   ❄️ 겨울 쿨
```

여기에 세 번째 축(선명도)을 더해 같은 사분면 안의 미묘한 차이를 잡습니다. 봄은 맑고(clear), 여름은 부드럽고(muted), 겨울은 대비가 강합니다(vivid).

### 3축 정규화

각 측정값을 로지스틱 함수로 `[0, 1]` 구간에 매핑합니다.

```python
adjusted_b = b* + 0.30·(L* − 50)          # 명도 보정 노란기

warm  = σ( (adjusted_b − 21) / 10 )
light = σ( (ITA° − 48) / 12 )
clear = σ( (C*   − 22) / 7  )
```

> **warm 축이 h°에서 `adjusted_b`로 바뀐 경위 (2026-08-12, ADR-010)** — 초기 설계는 `σ((h° − 62)/5)`였고, 62°는 문헌 기반 잠정값이었습니다. 첫 수동 검증셋(76장, 확신 케이스 한정)에서 h° 단일 신호의 정확도 상한이 ~66%로 실측됐는데, 임계값을 역산해도 최적점이 정확히 62°였습니다 — **틀린 것은 상수가 아니라 특징이었다**는 뜻입니다. 노란기의 절대량(`b*`)에 명도(`L*`) 보정을 더한 조합이 사람의 웜/쿨 지각과 더 맞았고(LOOCV 비교), L* 기울기는 무제약 적합값(1.93)이 교과서적 쿨 사례를 뒤집는 것을 확인한 뒤 **교과서 사례를 제약으로 둔 스윕**의 평탄 구간 중앙(0.30)으로 정했습니다. 도메인 테스트의 로지/페일 쿨 패치가 그 제약을 회귀로 지킵니다.

### 프로토타입과 거리

각 계절을 3차원 공간의 한 점으로 정의합니다.

| 계절 | warm | light | clear |
|---|---|---|---|
| 🌸 봄 웜 | 1.00 | 0.90 | 0.85 |
| ☀️ 여름 쿨 | 0.00 | 0.88 | 0.15 |
| 🍂 가을 웜 | 1.00 | 0.12 | 0.40 |
| ❄️ 겨울 쿨 | 0.00 | 0.15 | 0.90 |

입력 좌표에서 각 프로토타입까지 **가중 유클리드 거리**를 재고, 소프트맥스로 확률화합니다.

```python
distance_k = √( Σᵢ wᵢ · (protoₖ,ᵢ − pointᵢ)² )
P(seasonₖ) = softmax( −distance_k / T )
```

축 가중치는 `(warm=2.0, light=1.0, clear=0.7)`. 언더톤에 가장 큰 무게를 주는 이유는 퍼스널 컬러 이론에서 웜/쿨이 1차 분기이고 나머지는 그 안의 세부 조정이기 때문입니다.

### 왜 if-else 트리가 아닌가

```python
# 이렇게 하지 않았다
if hue > 62:
    return SPRING if ita > 48 else AUTUMN
else:
    return SUMMER if ita > 48 else WINTER
```

세 가지 이유입니다.

1. **경계에서 확률이 부드럽게 변합니다.** `h° = 61.9`와 `62.1`이 완전히 다른 답을 내놓으면 안 됩니다. 실제로는 "둘 사이 어딘가"가 정직한 답입니다.
2. **신뢰도를 정직하게 표현할 수 있습니다.** 트리는 항상 100% 확신하는 척합니다.
3. **8세부 타입 확장이 프로토타입 추가만으로 끝납니다.** 트리는 깊이가 늘고 조건이 조합 폭발합니다.

### 캘리브레이션 가능성

모든 임계값은 `CalibrationConfig` 하나에 모여 있습니다. 실측 데이터가 쌓이면 **코드를 건드리지 않고** 이 값만 최적화하면 됩니다. 프로토타입 좌표 자체도 학습 대상이 될 수 있습니다.

> 현재 값은 공개 문헌의 피부 CIELab 분포 범위에 근거한 **잠정값**입니다. 실측 캘리브레이션은 Step 5에서 진행합니다.

## 5. 신뢰도 보고

결과에 확률 최댓값만 붙이면 거짓말이 됩니다. 피부 픽셀이 200개뿐인 저해상도 사진과 5만 개가 잡힌 정면 사진이 같은 확신을 가질 수는 없습니다.

```
최종 신뢰도 = P(최상위 계절) × 품질 계수
```

**품질 계수**는 두 요소로 감쇠합니다.

| 요소 | 임계 | 효과 |
|---|---|---|
| 피부 픽셀 수 | < 2,000 px | 최대 0.55배까지 감쇠 + 경고 |
| `L*` 사분위 범위 | > 18 | 최대 0.5배까지 감쇠 + 경고 |

### 언더톤은 따로 보고합니다

웜/쿨 2분류는 4분류를 병합한 것이므로 **항상 더 견고합니다**. 4계절 판정이 애매해도 언더톤만큼은 자신 있게 말할 수 있는 경우가 많습니다.

```
가을 웜 46% / 겨울 쿨 44% / 봄 웜 8% / 여름 쿨 2%
→ 4계절 판정: 애매함 (경고)
→ 언더톤 판정: 웜 54% — 이것도 애매
```

```
봄 웜 47% / 가을 웜 34% / 겨울 쿨 11% / 여름 쿨 8%
→ 4계절 판정: 애매함 (경고)
→ 언더톤 판정: 웜 81% — 확실함 ✓
```

두 번째 경우 사용자에게 *"웜톤인 것은 확실하고, 봄과 가을 사이에 계십니다"* 라고 말할 수 있습니다. 최상위 하나만 내보냈다면 이 유용한 정보가 통째로 버려졌을 겁니다.

### 경계 판정은 격차로 본다

절대 확률이 아니라 **1위와 2위의 격차**를 봅니다. 4분류에서 55%는 나머지가 15%씩 흩어졌으면 확실한 결과지만, 2위가 44%라면 사실상 동점입니다. 절대값만 보면 이 둘을 구분할 수 없습니다.

## 6. 알려진 한계

정직하게 남겨둡니다.

**축 간 상관** — `b*`가 `h°`(색상각)와 `ITA°`(명도각) 양쪽 계산에 들어갑니다. 세 축이 완전히 독립적이지 않습니다. 실측 데이터가 모이면 PCA나 백색화로 탈상관하는 것을 검토합니다.

**메이크업** — 파운데이션과 립스틱은 측정 대상 자체를 바꿉니다. 마스킹으로 입술은 제외할 수 있지만 파운데이션은 방법이 없습니다. UI에서 노메이크업 사진을 권장 안내합니다.

**보정 필터** — 소셜 미디어 필터가 적용된 사진은 피부 색채 정보가 이미 소실된 상태입니다. 검출할 방법이 마땅치 않습니다.

**캘리브레이션 근거** — 현재 상수는 문헌 범위 기반 추정입니다. 실측 라벨 데이터로 검증하기 전까지는 절대 정확도를 주장하지 않습니다.
