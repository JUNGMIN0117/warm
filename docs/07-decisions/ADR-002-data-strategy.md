# ADR-002. 규칙 엔진 우선, 학습 모델은 대조군

- **상태**: 채택
- **결정일**: 2026-08-07
- **관련**: ADR-001, [03-color-theory.md](../03-color-theory.md)

---

## 맥락

원본 프로젝트는 Selenium으로 *"웜톤 연예인"* / *"쿨톤 연예인"* 을 검색해 이미지를 모으고, 검색어를 그대로 라벨로 삼아 CNN을 학습시켰습니다. 결과는 val_accuracy 0.82였지만, 보고서는 이 수치를 신뢰하지 않았습니다.

재구축에서 학습 데이터를 어떻게 확보할지 결정해야 합니다.

---

## 검토한 선택지

### 안 A — 크롤링 재현 (원본 방식)

**기각 사유** — 라벨 자체가 오염되어 있습니다.

- *"웜톤 연예인"* 이라는 검색어의 결과는 **누군가의 주관적 진단**입니다. 같은 인물이 두 검색어 모두에서 나오는 경우도 흔합니다.
- 연예인 사진은 **전문 조명 + 메이크업 + 후보정**을 거칩니다. 우리가 재려는 자연 피부색이 이미 사라진 상태입니다.
- 오차의 출처를 분리할 수 없습니다. 성능이 낮게 나왔을 때 전처리 문제인지, 라벨 문제인지, 모델 용량 문제인지 알 방법이 없습니다. **디버깅 불가능한 파이프라인**입니다.
- 저작권·초상권 리스크가 있습니다.

### 안 B — 공개 얼굴 데이터셋

FairFace, UTKFace 등이 있지만 **퍼스널 컬러 라벨이 없습니다.** 인종·나이·성별 라벨은 있어도 웜/쿨은 없습니다. 결국 라벨을 우리가 만들어야 하는데, 그러면 안 C와 같아집니다.

다만 **얼굴 이미지 자체**는 여기서 얻고, 라이선스도 명확합니다. 부분적으로 채택합니다.

### 안 C — 규칙 엔진 우선 ✅

---

## 결정

**3단계로 진행합니다.**

### Phase 1 — 색채학 규칙 엔진 (현재)

CIELab 좌표 위에서 결정론적으로 동작하는 분류기를 먼저 만듭니다.

- 학습 데이터 **0건**으로 오늘 당장 동작합니다
- 결과를 세 개의 수치(`h°`, `ITA°`, `C*`)로 **완전히 설명**할 수 있습니다
- 모든 임계값이 `CalibrationConfig` 하나에 모여 있어 나중에 튜닝 가능합니다
- **영구 폴백**으로 남습니다 — 모델 서빙이 실패해도 서비스는 계속 동작합니다

### Phase 2 — Pseudo-label 생성 및 CNN 학습

공개 데이터셋(라이선스 확인 필수)의 얼굴 이미지에 Phase 1 파이프라인을 돌려 라벨을 생성하고, 그걸로 CNN을 학습시킵니다.

여기서 자연스럽게 나오는 질문이 있습니다 — **"규칙 엔진이 만든 라벨로 학습한 모델이 규칙 엔진보다 나을 수 있는가?"**

원리상 가능합니다. 규칙 엔진은 마스킹된 피부 픽셀의 색채 통계만 봅니다. CNN은 규칙 엔진이 버리는 정보(피부 질감, 홍조 분포, 조명 방향)에 접근할 수 있고, 이것들이 진짜 신호와 상관되어 있다면 노이즈를 평균해내면서 원본 규칙보다 나은 일반화에 도달할 수 있습니다. 반대로 규칙 엔진의 편향을 그대로 증폭시킬 수도 있습니다.

**어느 쪽인지는 측정해야 알 수 있습니다.** 그게 Phase 3입니다.

### Phase 3 — 수동 검증셋으로 비교 평가

소규모(200~300장) 검증셋을 사람이 직접 라벨링하고, 규칙 엔진과 CNN을 같은 셋에서 비교합니다.

| 측정 항목 | 목적 |
|---|---|
| 언더톤 2분류 정확도 | 1차 축이 맞는가 |
| 4계절 정확도 | 실사용 성능 |
| 신뢰도 캘리브레이션 (ECE) | 80%라고 말할 때 실제로 80%인가 |
| 동일 인물 다른 조명 일관성 | **원본이 실패한 지점** |
| Grad-CAM 히트맵 | 피부를 보는가 윤곽을 보는가 (**P2 검증**) |

마지막 두 항목이 이 프로젝트의 핵심 실험입니다. 원본 보고서가 우려했던 *"얼굴의 윤곽이 학습될 수도 있다"* 를 실제로 확인하거나 반증합니다.

## 크롤러는 어떻게 하는가

**별도 모듈로 구현하되, 학습 파이프라인에서는 분리합니다.**

원본 프로젝트의 핵심 구성요소였으므로 재구현 자체는 의미가 있습니다(포트폴리오의 "복원" 서사). 다만 다음을 지킵니다.

- `robots.txt` 준수 및 요청 간 지연
- 수집 이미지는 **정성 검토용**으로만 사용, 학습 라벨로 쓰지 않음
- 저장소에 이미지를 커밋하지 않음 (`.gitignore`)
- 문서에 법적 고려사항 명시

Selenium 대신 **Playwright**를 씁니다. 원본이 겪었을 `find_element_by_css_selector` 계열 API 폐기 문제와 드라이버 버전 관리 문제가 없습니다.

## 결과

### 얻는 것

- **첫날부터 동작하는 제품**이 있습니다. 학습이 끝날 때까지 아무것도 못 보여주는 상황을 피합니다.
- **오차의 출처를 분리할 수 있습니다.** 규칙 엔진이 기준선이므로, CNN이 못하면 모델 문제고 둘 다 못하면 전처리 문제입니다.
- **모델 없이도 서비스가 죽지 않습니다.** 추론 서버 장애 시 규칙 엔진으로 폴백합니다.
- 포트폴리오 관점에서, *"모델을 만들었다"* 보다 **"모델이 정말 필요한지 측정했다"** 가 더 강한 서사입니다.

### 치르는 비용

- **초기 정확도가 캘리브레이션 상수의 품질에 전적으로 달려 있습니다.** 현재 값은 문헌 기반 추정치이며, Phase 3 전까지 절대 정확도를 주장할 수 없습니다.
- 규칙 엔진이 놓치는 신호(질감, 홍조 패턴)를 Phase 2 전까지 활용하지 못합니다.
- 검증셋 수동 라벨링에 실제 공수가 듭니다.

### 정직성 원칙

**Phase 3를 통과하기 전까지 UI에서 정확도 수치를 광고하지 않습니다.** 대신 신뢰도 계수와 확률 분포를 항상 함께 표시하고, 재미로 쓰는 참고 지표임을 명시합니다.
